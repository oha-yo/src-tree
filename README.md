# src-tree（ソースを AI に渡す）

ローカルのプロジェクトのフォルダを選ぶと、**解析に必要なファイルだけの tree** を表示し、tree やソースを、**チャット型 AI（Copilot など）に貼りやすい形でコピー**する道具。ブラウザだけで動き、ファイルはどこにも送らない。

AI エージェントは使えないが、チャット型 AI（Copilot）は使える客先で、古い Java プロジェクト（Spring 以前、WAS で動くバッチや Web システム、Java 1.6 など）を調べるために作った（2026-10-05）。

## 使い方
1. `index.html` をブラウザで開く（Chrome・Edge・Firefox）
2. 「フォルダを選ぶ」でプロジェクトのフォルダを選ぶ
3. 「tree をコピー」で、チャットに tree を貼る
4. tree のファイル（またはフォルダ）にチェックを付けて「選んだファイルをコピー」。多いときは「1/3 をコピー」「2/3 をコピー」…と分けてコピーする
5. ファイル名を押すと、下にそのファイルの中身が出る（「このファイルをコピー」で1つだけコピー）

## できること
| 機能 | 内容 |
|---|---|
| フォルダの読み込み | Chrome・Edge は「フォルダの閲覧の許可」で読み、git pull のあとは「**読み込み直し**」で選び直さずに読み直せる。Firefox は `<input webkitdirectory>` で読む（ブラウザが「アップロードしますか」と聞くことがあるが、実際には送らない） |
| 選んだフォルダの表示 | 読み込んだら「1. フォルダを選ぶ」の下に、フォルダの名前（📁）、すぐ下のフォルダとファイル、対象のファイルの数、一番新しい更新日時を出す。ブラウザはフルパスを教えないので、名前と中身で「あのフォルダだ」と確かめてもらうため |
| 読み込むもの | 「フォルダを選ぶ」と、外すフォルダ以外をたどってファイル名を集め、**対象の拡張子のファイルだけ、中身をすべて読む**（行数・文字コードを出すためと、選んだらすぐコピーできるようにするため）。ほかのファイルは名前だけで、中身は読まない。読んだ中身はこのページのメモリーに置くだけで、ページを閉じるか「**クリア**」で消える。「クリア」は拡張子などの設定を残して、最初の状態に戻す |
| 絞り込み | 対象の拡張子（初期設定：`.java` `.jsp` `.xml` `.properties` `.sql` `.sh` `.bat`）と、外すフォルダ（初期設定：`.git` `.svn` `bin` `build` `classes` `target` `out` `.settings` `.metadata` `.idea` `node_modules`）。変えるとその場で作り直す |
| 文字コード | 自動：**UTF-8・Shift_JIS・EUC-JP** を判定する（古い Java のソースは Shift_JIS が多く、まれに EUC-JP もある）。UTF-8 として正しく読めれば UTF-8。だめなら Shift_JIS と EUC-JP のうち正しく読めるほう。両方で読めるときは、**0x80〜0xA0 のバイトがあれば Shift_JIS**（EUC-JP はこの範囲を 0x8E・0x8F 以外使わず、Shift_JIS はひらがな・カタカナの1バイト目が 0x82・0x83 のため）。それでも決まらなければ、読んだ結果の日本語らしさで選ぶ。Shift_JIS は「SJIS」、EUC-JP は「EUC」の印。決め打ちもできる |
| tree | 中身が1つだけのフォルダは `src/com/example/order/` のようにまとめて書き、各ファイルに行数を添える（AI に「どれが大きいか」が伝わる）。**「tree をコピー」は画面で見えているとおり**にコピーする：閉じているフォルダは `WebContent/  … (ファイル 3 個、12 行)` のように中身を省いて1行にする（関係のないフォルダを閉じてから渡せば、チャットの文字数の節約にもなる）。開け閉めの状態は、選択を変えても保つ |
| ファイル名で探す | tree の上の欄に入れると、その場で tree を絞り込む（見つかったファイルと親のフォルダだけ残し、一致した部分に色を付ける）。大文字・小文字は区別しない。**空白で区切ると「かつ」**（`order dao`）、**`*` と `?` が使える**（`*Action.java`。`*` があるときはファイル名全体で比べるので、途中を含むなら `*Batch*`）、**`/` を含むとパス全体で探す**（`WEB-INF/`）。探している間は「すべて選ぶ」が「見つかったものを選ぶ」になり、「tree をコピー」は見つかったものだけになる（最後に絞り込みの条件を書く）。Esc か「×」でやめる |
| 中身で探す（grep） | 探す欄の左を「中身（grep）」にすると、読み込んだファイルの中身から探す（中身は読み込んだときにメモリーにあるので、読み直さない）。空白もそのまま探す。「大文字・小文字を区別」「正規表現」も選べる。tree は一致した行のあるファイルだけになり、ファイルごとに件数が出る。tree の下に一致した行の一覧（行番号つき）が出て、**行を押すと下の欄でその行に飛ぶ**。「**grep 結果をコピー**」で `【src-tree】… の中身を「T_ORDER」で検索（ファイル 3 個、7 件）` の見出しとファイルごとの行をコピーする（AI に「このテーブルを使っている所」を伝えるときなど）。一覧に出すのは最初の 1000 件まで（コピーには全部入る） |
| ソースのコピー | ファイルごとに `### パス（行数）` の見出しとコードの囲み（言語付き）を付ける。ソースに ```` ``` ```` があっても壊れないよう、それより長い ` で囲む |
| 分けてコピー | 1回の上限（初期設定 **2500 行**。Copilot は 3000 行くらいまで貼れて、4000 行あたりから貼れなかった）を超えたら、何回かに分ける。ファイルの途中では切らない。1つのファイルだけで上限を超えるときは「1〜2500行目／全3003行」のように行で区切る。分けたものの先頭には `【src-tree】プロジェクト名 のソース 1/3（ファイル 5 個、37 行）` と書く |

## 気をつけること
- **`bin` を外すフォルダに入れている**のは、Eclipse がコンパイルした `.class` を `bin/` に出すため。ただ、古いプロジェクトでは**起動用のシェル（`.sh`）を `bin/` に置いている**こともある。その場合は「外すフォルダ」から `bin` を消す
- 2MB より大きいファイルは読み込まない（tree には「読み込まず」と出る）
- ソースをチャットに渡してよい範囲は、**客先のルール（Copilot の利用規程など）に従う**。どのファイルを渡すかは、人がチェックで選ぶ作りにしている

## ブラウザの決まりで、できないこと
| できないこと | 理由と、代わりにしたこと |
|---|---|
| 選んだフォルダのフルパスを出す | ブラウザがページにフルパスを教えない（ユーザー名や客先名が入ることがあるため）。名前とすぐ下の中身を出して確かめてもらう |
| ダウンロード・デスクトップ・ユーザーのフォルダそのものを選ぶ（Chrome・Edge） | ブラウザが「システムファイルが含まれている」として断る。中のプロジェクトのフォルダを選ぶ |
| Firefox で「読み込み直し」 | Firefox は選んだフォルダを覚えておく仕組み（File System Access API）がないので、選び直す。外すフォルダ（`.git` など）の中も一度は全部渡されるので、大きなプロジェクトでは時間がかかる |
| ページを閉じても、選んだフォルダや許可を覚えておく | ブラウザの中にフォルダを保存すればできるが、客先で使うので**あえてしない**。ページを閉じれば、許可も読んだ中身も消える |
| ファイルが変わったら自動で読み直す | ファイルの変更を知らせる仕組みが、まだ広く使えない。「読み込み直し」を押す |
| grep の結果から、エディタ（Eclipse など）でそのファイルを開く | ページから PC のアプリを起動できない。下の欄でその行に飛ぶところまで |
| ファイルを書き換える | 書き込みの許可も頼めるが、読むだけの道具なので頼まない |
| 文字コードを確実に見分ける | ブラウザに文字コードを判定する機能がない。正しく読めるかどうかと、バイトの並びから推し量る（まれに外れたら「文字コード」で決め打ち） |

## 構成
```
src-tree\
├─ index.html          … ローカルで開くページ
├─ src-tree.js         … 本体（画面の部品もこの JS が作る）
├─ src-tree.css        … 見た目（.src-tree-tool の中だけに効く）
└─ test\
    ├─ make_sample.py  … 試験用の「古い Java プロジェクト風」のフォルダと、同じ中身の sample-data.js を作る
    ├─ sample-data.js  … 回帰テストで読み込むファイル（make_sample.py が作る）
    ├─ regress.html    … 回帰テスト（開くと自動で操作して、結果を expected.json と比べる）
    ├─ regress.js
    └─ expected.json   … 回帰テストの期待する結果
```

## 版の番号
画面の右上（「1. フォルダを選ぶ」の横）に `src-tree v1.1.0` のように出す。番号は `src-tree.js` の先頭の `VERSION` で決める。上げるときは、次の3つをそろえる。
1. `src-tree.js` の `VERSION`
2. `CHANGELOG.md`
3. ブログの固定ページの読み込みの `?v=`（ブラウザに古いファイルを使わせないため）

## 回帰テスト
直したあとで、ほかの動きが変わっていないかを確かめる。
```
cd src-tree
python -m http.server 8000
```
ブラウザで `http://localhost:8000/test/regress.html` を開くと、試験用のプロジェクトを読み込んで、tree のコピー、分けてコピー、ファイル名で探す、grep、設定の変更、クリアなどを自動で行い、結果を `test/expected.json` と比べる。「OK：29 項目すべて同じです」なら変わっていない。
- 動きを**意図して**変えたときは、`regress.html?update` を開いて、出てきた JSON を `test/expected.json` に保存し直す
- 試験用のプロジェクトを変えたときは、`python test/make_sample.py` で `sample-data.js` を作り直してから、`expected.json` も作り直す

### ページへの置き方（ローカルでもブログでも同じ）
```html
<link rel="stylesheet" href="（場所）/src-tree.css">
<div class="src-tree-tool"></div>
<script src="（場所）/src-tree.js"></script>
```
ブログ（oha-yo.com）に載せるときは、clip-tools と同じく、売り場を固定ページ `/tools/src-tree/`、倉庫を `/assets/src-tree/` にする予定。見た目は `.src-tree-tool` の中だけに効き、部品に id を使わない（テーマとぶつからないため）。
